Queues in Postgres

By Ada Example, 30 September 2026

A job queue in Postgres needs one statement that many workers can run at the same time without taking the same job. The answer is SELECT … FOR UPDATE SKIP LOCKED, and it has been in Postgres since version 9.5.

Why SKIP LOCKED

Without SKIP LOCKED, the second worker waits for the lock of the first one. With it, the second worker takes the next free row. So the queue stays fast, and no job runs two times at once.

  • One row for each job.
  • A lease with a time limit, so that a job of a dead worker comes back.

Read the documentation of SELECT for the details. The café on the corner has nothing to do with this, but the “é” must survive.
